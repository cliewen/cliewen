# CH-079 — Make every live evidence-model carrier state the v0.9 contract

## What

Serve P-008/M-032 by making Cliewen's live public, contributor, agent, scaffold, architecture, capability, implementation, CLI, plugin, and guide-site carriers state one v0.9 evidence contract. Record the lasting project rule that a methodology contract change inventories and repairs every live carrier that states the affected contract in the same change. Supersede PDR-013's executable-only core wording, refine C-006 and the shared lifecycle guidance, and make the Human acceptance-brief path part of the protected verifiable thread without presenting it as executable code evidence.

Repair the canonical `clue-extract` and `clue-verify` sources, regenerate both skill output trees, synchronize repository and scaffold pull-request templates, and update the complete live inventory established by AN-011. Add focused guards and acceptance evidence for classified positive/negative evidence, single-direction evidence, Human proof, per-criterion `@draft`, supported Go/JVM/Cucumber carriers, activation granularity, and the boundary that `clue validate` validates references but does not execute tests. Add an `[Unreleased]` changelog entry explaining the corrected user-facing extraction and evidence guidance.

## Why

AN-011 demonstrated that the v0.9 validator, tests, generated-skill drift checks, and guide build can all pass while live carriers contradict the evidence model they describe. Some instructions still say `clue` recognizes only one reference, every active criterion needs executable positive and negative evidence, or an entire capability must remain draft when one criterion is unproven. Other protected core carriers still end the verifiable thread exclusively in tests even though a genuine Human-class criterion is proven by the pull request's acceptance brief.

Leaving those carriers inconsistent makes the methodology mechanically green but semantically unreliable. Because the repair changes what the protected core connects, C-013 requires an explicit decision record and human acceptance. M-032 intentionally keeps the repair in one full change so accepted `main` never states the shared contract two ways.

## Decision boundary

This change decides that every live carrier stating an affected methodology contract is inventoried and updated in the same change, and that the protected verifiable thread ends in acceptance evidence: classified executable evidence for machine-proven criteria or the acceptance brief for genuine Human-class criteria. Stable anchors guard only the evidence-model claims repaired here; the general carrier-inventory obligation remains agent-enforced because no current mechanism derives the carrier set for an arbitrary contract.

This change does not create a machine-readable carrier registry, execute tests from `clue validate`, change the supported test-carrier set, alter historical analyses or completed-plan descriptions, implement extraction rehearsal, or open the configuration and distributed-work interfaces reserved for later P-008 milestones.
