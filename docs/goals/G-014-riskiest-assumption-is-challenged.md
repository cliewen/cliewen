# G-014 — A plan's riskiest assumption is challenged before commitment

**Who wants it:** anyone about to commit a Cliewen repository to a course of work — the maintainer approving a plan, and every agent that proposes one (2026-09-12, from [AN-024](../analysis/AN-024-methodology-review-acceptance-and-learning.md)).

**Why:** Cliewen's thread proves that the built thing matches the stated criterion. It cannot prove the criterion was the right thing to state. A criterion, the implementation that satisfies it, and the test that guards it are usually written by the same author in the same sitting, so a single mistaken assumption propagates through all three and comes out the far end looking verified. Scenario-to-test alignment is alignment, not evidence that the scenario describes the outcome anyone wanted.

The cost lands where correction is most expensive. An assumption caught while a plan is still a proposal costs a paragraph; the same assumption caught at acceptance costs the campaign. Agents make this worse rather than better: an agent asked to plan will plan, fluently and immediately, and fluency reads as confidence. Nothing in the method currently asks what would have to be true for this plan to be worth doing, or what the cheapest way to find out is.

The method already prioritises risk in the analysis workflow and requires verifiable milestones in planning. Neither obliges anyone to name the assumption most likely to be wrong before the repository commits to acting on it.

**Success looks like:**

- Before a consequential commitment, the assumption most likely to undermine the plan is named, together with a credible alternative, the cheapest useful test, and the result that would stop or revise the work.
- The challenge is proportional: a small, reversible, well-understood change proceeds without ceremony, and prototypes are never required universally.
- A milestone may deliver decision-changing evidence rather than a feature, and the method says so, so investigating is a legitimate way to spend a milestone rather than a detour from delivery.
- Repository experience is cited as evidence when challenging an assumption, and old guidance is treated as evidence to reassess rather than as standing authority.
- Both directions are demonstrable: a weak proposal that evidence redirected, and a sound proposal that proceeded without unnecessary investigation.
