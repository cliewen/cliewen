# Design — CAP-005 Index generation

One engine, two exposures ([ADR-019](../../decisions/ADR-019-init-regenerates-indexes.md)): the scaffold package's index regeneration runs inside `clue init` after materialization, and stands alone as `clue scaffold` via an exported entry point (`Regen`) that materializes nothing.

- **The regeneration contract mirrors the judge**: the set of READMEs regenerated (docs/README.md and each first-level folder README) is exactly the set `checkIndexes` validates, and the wanted-entry rule (sibling artifacts plus markdown-bearing subfolders) is the same — including subfolder coverage, where any live link into the subfolder counts, so a curated descendant entry survives regeneration exactly as it survives validation. A validator rule the regeneration violates fails the AC-026 test the moment it lands.
- **An appended row states its record** ([ADR-041](../../decisions/ADR-041-index-rows-state-their-record.md)): `- [<id> — <title>](<file>) · \`<badge>\``, read from the target's parsed frontmatter so a YAML-quoted title is spelled as its value rather than its quoting. The badge is `enforcement` for a constraint, because its register exists to publish the class, and `status` for every other artifact. A constraint missing readable enforcement falls back to the plain link with an artifact missing any core field; a subfolder row states a section and carries no title or badge. `clue validate` counts the rows that state only their own link (AC-074) and direct constraint rows whose badge disagrees with enforcement (AC-138) — it never rewrites them, so existing rows, including their curated tails, survive exactly as before. The badge itself is the one part of a kept row regeneration does refresh ([ADR-064](../../decisions/ADR-064-regeneration-owns-the-index-badge.md), AC-159), because it is a copy of a frontmatter field rather than a judgement anyone made.
- **An appended row says what the artifact is about** ([ADR-046](../../decisions/ADR-046-index-rows-say-what-the-artifact-is-about.md)): the row gains ` — <description>`, seeded by `corpus.RowDescription` from the target's own body — a lede paragraph beneath the H1 (written with a `#` or a setext underline) where one exists, otherwise the first sentence of the first paragraph under the first heading. Structure is skipped rather than read: headings either way, table rows, bulleted and ordered list items, blockquotes, fenced and indented code, HTML tags, and horizontal rules. The sentence is bounded at a word boundary so the row stays one line, backing off to a rune boundary where the prose carries no spaces to cut on, so a README can never be left invalid UTF-8 (AC-096). Every link is reduced to its label, a code span included, because the block's link reading knows nothing about spans and a quoted placeholder target would leave generation emitting a corpus the judge rejects. A candidate that cannot be made safe is **declined rather than repaired** — a link label carrying its own brackets defeats any single reduction pattern while the judge matches the residue anyway, and an index marker or HTML comment would truncate the block on the next run — so the shorter row is emitted instead. An artifact with no readable sentence keeps that shorter row rather than carrying an empty tail (AC-097). The seed is a first draft: regeneration rewrites nothing that exists, nothing backfills a description, and a curated row's description survives — though not once its target is gone (AC-160, which succeeds the retired AC-098 now that the badge beside it refreshes). `clue validate` counts the rows still saying nothing (AC-099). That count is disjoint from the filler count because `IndexDescriptionBacklog` applies the same label-versus-filename test `IndexRowBacklog` does, and not because of the status badge: a filler row can be hand-given a badge while ADR-041's backlog is worked down, and reading the badge alone counted one such row in both populations. A row stating a record *without* the badge the generator always writes is adopter prose in a shape no release produced, and is deliberately counted by neither.
- **Prose safety**: only the block between the `clue:index` markers is rewritten; the file's own line endings are preserved; a marker-less taxonomy README gains an appended block; a lone or reversed marker is an error naming the file — never a guess.
- **Nothing is invented**: missing folder READMEs are reported (recursively, matching the validator's reading) and left missing; a root without a `docs/` tree exits 1 with the error on stderr — `clue init` is the tool that materializes, and a silent no-op would mask a mistyped path.
- **Report surface**: `indexed` lines per regenerated README, `missing` lines per absent folder README, one summary line — same vocabulary as `clue init`.
