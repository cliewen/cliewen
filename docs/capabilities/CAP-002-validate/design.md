# Design — CAP-002 `clue validate`

## Shape

`cmd/clue` (entry, stdlib `flag` only — no CLI framework until a second command earns one) and `internal/corpus` (scan + rules). The read-only `clue next` orientation command shares the corpus scanner and milestone-table parser but does not participate in validation. Two phases:

1. **Scan** (`corpus.Scan`): walk `docs/` and `changes/`, split YAML frontmatter from body (CRLF-normalized first — Windows checkouts), parse via yaml.v3 ([IDR-007](../../decisions/IDR-007-frontmatter-parsing-is-yaml-and-rejects-hidden-duplicates.md)), build the artifact graph keyed by `id`. Discovery is by frontmatter, never by path (Foundation §4). A file with no frontmatter is a finding; a taxonomy folder README (`docs/README.md` or `docs/<folder>/README.md`), and any deeper README whose header has no `id`, is a typed document rather than an artifact and is held to `type: index` and a title, while a README with an `id` below the taxonomy, such as a capability's, stays an artifact ([PDR-065](../../decisions/PDR-065-markdown-carries-frontmatter-by-default.md)). Outside the corpus, `checkDeliveredHeaders` requires a `type` and `title` on each file in `corpus.DeliveredMarkdown` that is present and on every file of a skill marked `cliewen-skill: true`, skipping a `.claude/skills` mirror that is a symlink so one file is not reported twice; the pull-request template is deliberately absent from that list.
2. **Rules** (`corpus.Validate`): core fields, frontmatter hygiene (no UTF-8 byte-order marks or complete second frontmatter blocks opening an artifact body), duplicate IDs, status vocabulary per type (one default lifecycle `draft → active` — no `retired`; retirement is deletion, not a status, per [ADR-034](../../decisions/ADR-034-retirement-is-deletion.md) — plus the `statusVocabExceptions` map in `rules.go`, mirrored by the docs/README.md table; a type the validator does not recognize is an adopter extension checked against the default rather than rejected — ADR-025, ADR-026), link resolution (M-xxx harvested from plan bodies and live AC IDs harvested from criteria), retirement bookkeeping (`corpus.checkSupersedes`: an artifact's `supersedes:` field naming an ID that still resolves to a live artifact, that names its own ID, or that is claimed by more than one artifact all fail; `checkLinks` names the successor when a dangling link matches a `supersedes:` entry elsewhere — ADR-034 — except from a `completed` plan, whose `links:` record what a finished campaign referenced rather than navigating a reader anywhere and are unavailable for repair under [C-008](../../constraints/C-008-completed-plans-immutable.md), so a retired target is accepted there while an active plan still repoints and an ID no artifact ever declared still fails everywhere ([ADR-063](../../decisions/ADR-063-a-frozen-plan-links-are-historical.md))), bounded provenance (`checkProvenance`: inferred non-decisions declare low/high reversal cost and a high-cost member of an active capability's one-edge slice blocks activation, while inferred decisions remain a separately visible signature backlog), incident edges (`checkReality`: `reality: contradicted` belongs to analysis and links a capability or live criterion), required activated system overviews (`checkSystemOverviews`: a corpus carrying either convention folder needs both canonical README paths, and an explicit scaffold marker remains red until an agent replaces it with repository truth), README.md in every `/docs` folder, index-block integrity on taxonomy READMEs (`<!-- clue:index:start/end -->`: block links must exist, siblings and artifact-bearing subfolders must be referenced; separately, `corpus.IndexRowBacklog` counts rows whose label restates only their own link, `corpus.IndexDescriptionBacklog` counts rows that state their record but say nothing about it, and `corpus.IndexRowConstraintBadgeBacklog` counts direct constraint rows whose badge disagrees with enforcement; the CLI names all three behind `--index-rows` as reported populations, never `Issue`s, per [ADR-041](../../decisions/ADR-041-index-rows-state-their-record.md) and [ADR-046](../../decisions/ADR-046-index-rows-say-what-the-artifact-is-about.md)), constraint register fields (`source` non-empty, `enforcement: machine|partial|agent|human`, and the `**Checked by:**`/`**Residual:**` declarations `partial` and `human` owe — [ADR-017](../../decisions/ADR-017-conventions-are-constraints.md), [ADR-045](../../decisions/ADR-045-register-names-the-machine.md); the CLI reports the `agent` count as the promotion backlog and says nothing at zero), and the `--forbid-changes` gate.

2b. **Promoted conventions** (`corpus.checkTypeFields`, `checkProseLayout`, `checkSkippedTasks`, `checkProposalPlanItem`, `checkMilestoneStatus` in `conventions.go`, CH-110): the register rules that are about corpus *state*, each answering from the files in front of it. Per-type frontmatter extensions come from the `typeFields` map — `author`/`accepted-by` on decisions, `goal` on capabilities, with an empty `accepted-by` list counting as present and an unrecognized type checked against the core alone (C-009). Prose layout flags two running-text lines in a row, where a list marker opens text without being a continuation and fences, tables, frontmatter, blockquotes, HTML, and link definitions are structure (C-001). A `[-]` task under `changes/**/tasks.md` must carry prose after its checkbox (C-003); a `changes/*/proposal.md` must link a `P-`/`M-` identity or say `plan-less` (C-005); and a plan table declaring a `Status` column has its cells read against `todo | doing | done | dropped` (C-010). Provenance requires `reversal-cost` only while a non-decision is inferred, and rejects the field after verification; high cost blocks an active capability's one-edge slice while low cost permits deferral. C-007 is human-held guidance: image links and assets are valid, and the choice between Mermaid, ASCII art, and SVG is reviewed for clarity rather than treated as a validation verdict.

**The edge these share:** they are properties of the corpus as it stands. `clue validate` never reads a diff, a base revision, or history — a verdict computed from a transition depends on the caller's branch and clone depth rather than on the bytes under review ([ADR-044](../../decisions/ADR-044-judge-reads-state-not-transitions.md)). The register's transition rules are held elsewhere: `.github/scripts/completed-plans.sh` freezes a completed plan (C-008), the release gates require a version section (C-002), and branch protection holds the merge boundary (C-012).

3. **Outward references** (`corpus.checkExternalReferences`, `corpus.checkForeignPointers`, CH-095): a reference pointing outside the repository names what it points at — a full address for anything that has one, the `clue:` identity form for an artifact in another repository's corpus — and a bare forge number fails with the line a reader opens to. The bare-number scan skips fenced blocks, code spans, link targets, labelled links, anchors, and local citations; the malformed-pointer scan skips fenced blocks and code spans, so a documented example of the form is never mistaken for a claim. The rule is pure text: resolving a target needs the network, so it lives in `clue refs` and can never reach a verdict ([ADR-040](../../decisions/ADR-040-qualified-external-references.md)).

4. **AC↔evidence contract** (`corpus.checkACTests`, `internal/evidence`, ADR-071): declaration parsing retains canonical namespaces, proof classes, paired directions and legacy/Human/draft/retired semantics. Every executable reference now comes from the repository-owned version-one `.clue/evidence.yaml` exchange. The strict YAML reader rejects duplicate keys, extra documents, unknown fields, invalid versions, duplicate producers, unsafe paths, untracked source inputs, duplicate/conflicting executable identities, incomplete classification, stale inventories and exporter diagnostics. It never invokes a producer or parses framework syntax. A producer has an ID, optional framework/language descriptions, include/exclude scopes, normalized input fingerprints, references and optional diagnostics. An executable's identity is producer ID plus path plus subject; multiple suites can share a name or criterion without merging executables. Each reference carries a canonical criterion ID and source-qualified subject, with type and direction together when classified. All producers must pass before any references earn credit. Missing exports are diagnosed when active machine/legacy proof is required; Human/draft-only corpora need no fabricated export.

Scope patterns use slash-separated glob segments and `**` for zero or more complete segments. Exclusions prune directories; safe repository paths cannot traverse symlinks or escape the checkout. Every matching file is fingerprinted with CRLF normalized to LF. File additions, deletions, exporter/configuration changes and unreadable inputs invalidate the snapshot. Exact missing inputs fail; wildcard scopes may be empty and detect later additions. The output cannot fingerprint itself. Producers snapshot inputs before collecting references; complete aggregation rechecks every scope before atomically replacing the output. A command failure or diagnostic preserves the previous complete export. Input hashes prove freshness within declared scopes, not correct discovery, assertions or test results; exporter regressions and human review own those claims.

This repository's explicit `go run ./tools/export-evidence` command uses a compatibility producer outside the judge for existing Go/JVM/Cucumber conventions. Go declarations use the AST, preventing source strings/comments from supplying tests. Adopters receive `.clue/evidence/` examples through `clue init`; the agent establishes actual repository-owned producers rather than expecting a framework support list. Native tags/properties/markers are preferred, custom executable annotations/attributes/decorators next, stable names/titles last. Parameterized declarations count once; ordinary proximity comments and container AC tags do not supply proof. Gatling export must expose registered simulations and relevant assertions.

`corpus.AcceptanceEvidence` returns declaration and reference maps plus findings. Parity refuses those findings before deriving a target; coverage receives no executable proof from an invalid exchange. Ledger identities are declaration state, independent of an export's validity. `clue migrate` names a missing/invalid export as an establishment notice without fabricating references or rewriting tests.

5. **Derived coverage** (`corpus.Coverage`, `clue validate --coverage`): rolls each declared, non-retired criterion's evidence state up to its owning capability and prints `covered`, `partial`, or `gap` per capability, computed from `harvestACs`'s shared declarations and validated evidence import on every call — never written to disk, so it cannot drift the way a committed registry would (ADR-033).

6. **Derived reality gaps** (`corpus.RealityGaps`, `clue validate --reality-gaps`): rolls each incident analysis's capability or live-criterion links up to a sorted list of affected capabilities and the analyses that contradicted them. It reads only local corpus edges, writes nothing, and deliberately does not ingest production data ([ADR-035](../../decisions/ADR-035-bounded-provenance-and-reality-edges.md)).

7. **Derived read-cost backlogs** (`corpus.MultiDocumentBacklog`, `corpus.ContextSliceBudgetBacklog`, `clue validate --read-cost`): counts, without issuing a validation finding, durable non-completed artifacts whose bodies contain more than one rendered H1 — ATX or setext — outside fenced examples, tracking each fence's marker character and run length so a shorter fence demonstrated inside a longer one cannot invert the in-fence state, and durable identities, excluding those a completed plan owns, whose root-plus-direct-link context slice exceeds ADR-057's budget. The same `completed` exclusion covers both populations because a frozen plan's body and its `links:` list are equally unavailable for repair under [C-008](../../constraints/C-008-completed-plans-immutable.md). The slice measure resolves only direct links, not the context frontier, so a validator report does not traverse the graph merely to count what the default command prints. Both lists are sorted and named only behind the flag; their counts join the ordinary OK line.

8. **Identity ledger cross-check** (`corpus.checkLedger`, `internal/ledger`, CH-116 and CH-171): `.clue/id-ledger.yaml` is a versioned append-only event set folded into an in-memory `byID` map and per-prefix high-water map by one `Load()`. `checkLedger` cross-checks the corpus once a ledger exists: it rejects a live artifact or criterion whose ID is absent or effectively `reserved` or `retired`, requires a retained criterion tombstone to be ledger-retired, and rejects malformed or contradictory identity metadata. An opaque ID is never normalized or reissued; a numeric high-water mark includes every live, reserved, or retired event. `clue migrate` backfills one effective event per existing identity and converts the earlier counters-and-entries shape without renumbering ([ADR-048](../../decisions/ADR-048-corpus-wide-id-ledger.md), [ADR-068](../../decisions/ADR-068-git-serializes-identity-claims.md)). Allocation, remote coordination, synchronization, and lifecycle transitions belong to [CAP-010](../CAP-010-team-safe-identity-allocation/design.md); the judge remains checkout-only. `checkMilestoneCollisions` extends the same reconciliation to the `M` namespace (P-022/M-093), whose doors carry no frontmatter and so never reach `c.ByID`: it reports the same M-xxx ID declared in more than one milestone-table row anywhere in the corpus, and — once a ledger exists — an M-xxx ID whose ledger state disagrees with what the declaring row's own status implies.

## Deliberate limits (doors, not gaps)

- **Completed-plan immutability** — closed as a door rather than opened: it needs a base revision, which the judge will not have ([ADR-044](../../decisions/ADR-044-judge-reads-state-not-transitions.md)). It moved to CI, where a base is ordinary.
- **Layout linting beyond READMEs/indexes** — partly walked through by CH-110's prose-layout rule; a full markdown-shape profile remains a §4 default-on profile rule, later.

Exit codes: 0 valid · 1 issues · 2 usage error. Output is one `path: message` line per issue, sorted, so CI logs diff cleanly.
