# Design — CAP-002 `clue validate`

## Shape

`cmd/clue` (entry, stdlib `flag` only — no CLI framework until a second command earns one) and `internal/corpus` (scan + rules). Two phases:

1. **Scan** (`corpus.Scan`): walk `docs/` and `changes/`, split YAML frontmatter from body (CRLF-normalized first — Windows checkouts), parse via yaml.v3 ([decision log](../../decisions/log.md) row, 2026-07-12; demoted from ADR-003), build the artifact graph keyed by `id`. Discovery is by frontmatter, never by path (Foundation §4).
2. **Rules** (`corpus.Validate`): core fields, frontmatter hygiene (no UTF-8 byte-order marks or complete second frontmatter blocks opening an artifact body), duplicate IDs, status vocabulary per type (one default lifecycle `draft → active` — no `retired`; retirement is deletion, not a status, per [ADR-034](../../decisions/ADR-034-retirement-is-deletion.md) — plus the `statusVocabExceptions` map in `rules.go`, mirrored by the docs/README.md table; a type the validator does not recognize is an adopter extension checked against the default rather than rejected — ADR-025, ADR-026), link resolution (M-xxx harvested from plan bodies and live AC IDs harvested from criteria), retirement bookkeeping (`corpus.checkSupersedes`: an artifact's `supersedes:` field naming an ID that still resolves to a live artifact, that names its own ID, or that is claimed by more than one artifact all fail; `checkLinks` names the successor when a dangling link matches a `supersedes:` entry elsewhere — ADR-034), bounded provenance (`checkProvenance`: inferred non-decisions declare low/high reversal cost and a high-cost member of an active capability's one-edge slice blocks activation, while inferred decisions remain a separately visible signature backlog), incident edges (`checkReality`: `reality: contradicted` belongs to analysis and links a capability or live criterion), README.md in every `/docs` folder, index-block integrity on taxonomy READMEs (`<!-- clue:index:start/end -->`: block links must exist, siblings and artifact-bearing subfolders must be referenced), constraint register fields (`source` non-empty, `enforcement: machine|agent|human`; the CLI reports the `agent` count as the promotion backlog — [ADR-017](../../decisions/ADR-017-conventions-are-constraints.md)), and the `--forbid-changes` gate.

3. **Outward references** (`corpus.checkExternalReferences`, `corpus.checkForeignPointers`, CH-095): a reference pointing outside the repository names what it points at — a full address for anything that has one, the `clue:` identity form for an artifact in another repository's corpus — and a bare forge number fails with the line a reader opens to. Fenced blocks, code spans, link targets, labelled links, anchors, and local citations are never read as references. The rule is pure text: resolving a target needs the network, so it lives in `clue refs` and can never reach a verdict ([ADR-040](../../decisions/ADR-040-qualified-external-references.md)).

4. **AC↔test contract and test-purpose taxonomy** (`corpus.checkACTests`, CH-003, CH-072, CH-073, CH-087, CH-089): canonical criterion tags use segmented uppercase prefixes, decimal digits, and optional lowercase suffixes under [ADR-037](../../decisions/ADR-037-brownfield-ac-id-grammar.md); test purposes follow [ADR-005](../../decisions/ADR-005-test-reference-convention.md)/[ADR-006](../../decisions/ADR-006-test-purpose-taxonomy.md). Framework-native tags are the general convention, and Go's `testing` has none, so the Go harvester reads normalized function-name prefixes (`TestAC<digits>_…`, `TestSNAPSQS<digits>_…`, `TestUnit_…`, `TestSanity_…`, `TestArch_…`) from `*_test.go`; Cucumber `.feature` tags are scenario-level. JVM evidence is conservative source attribution under [ADR-036](../../decisions/ADR-036-jvm-evidence-per-executable.md): one Java or Kotlin executable carries one canonical AC identity, proof type, and direction through literal JUnit method tags or the stable named-executable fallback, while class tags, unsupported syntax, and metadata split across methods receive no classified credit and a diagnostic. The checker fails an active AC without a test, an undeclared or retired AC reference, an unclassified Go test, or duplicate declaration. A scenario that declares `Test-type: Unit|Integration|E2E|Performance` additionally requires evidence classified with that type in both positive and negative directions; `(single-direction)` records the narrow exception. [ADR-032](../../decisions/ADR-032-classified-ac-evidence.md) defines the proof-shape contract and preserves the one-reference contract for unannotated legacy scenarios. `Test-type: Human` needs no code evidence at all — the acceptance brief is its proof — and a per-criterion `@draft` tag-line token exempts one not-yet-proven criterion from the test requirement without retiring it or drafting its capability ([ADR-033](../../decisions/ADR-033-human-proof-and-draft-criteria.md)).

5. **Derived coverage** (`corpus.Coverage`, `clue validate --coverage`): rolls each declared, non-retired criterion's evidence state up to its owning capability and prints `covered`, `partial`, or `gap` per capability, computed fresh from `harvestACs`'s shared declaration-and-evidence walk on every call — never written to disk, so it cannot drift the way a committed registry would (ADR-033).

6. **Derived reality gaps** (`corpus.RealityGaps`, `clue validate --reality-gaps`): rolls each incident analysis's capability or live-criterion links up to a sorted list of affected capabilities and the analyses that contradicted them. It reads only local corpus edges, writes nothing, and deliberately does not ingest production data ([ADR-035](../../decisions/ADR-035-bounded-provenance-and-reality-edges.md)).

## Deliberate limits (doors, not gaps)

- **Completed-plan immutability** — needs git diff context, not just a tree snapshot.
- **Layout linting beyond READMEs/indexes** — default-on profile rule per §4, later.

Exit codes: 0 valid · 1 issues · 2 usage error. Output is one `path: message` line per issue, sorted, so CI logs diff cleanly.
