# Design — CAP-002 `clue validate`

## Shape

`cmd/clue` (entry, stdlib `flag` only — no CLI framework until a second command earns one) and `internal/corpus` (scan + rules). Two phases:

1. **Scan** (`corpus.Scan`): walk `docs/` and `changes/`, split YAML frontmatter from body (CRLF-normalized first — Windows checkouts), parse via yaml.v3 ([decision log](../../decisions/log.md) row, 2026-07-12; demoted from ADR-003), build the artifact graph keyed by `id`. Discovery is by frontmatter, never by path (Foundation §4).
2. **Rules** (`corpus.Validate`): core fields, frontmatter hygiene (no UTF-8 byte-order marks or complete second frontmatter blocks opening an artifact body), duplicate IDs, status vocabulary per type (one default lifecycle `draft → active` — no `retired`; retirement is deletion, not a status, per [ADR-034](../../decisions/ADR-034-retirement-is-deletion.md) — plus the `statusVocabExceptions` map in `rules.go`, mirrored by the docs/README.md table; a type the validator does not recognize is an adopter extension checked against the default rather than rejected — ADR-025, ADR-026), link resolution (M-xxx harvested from plan bodies and live AC IDs harvested from criteria), retirement bookkeeping (`corpus.checkSupersedes`: an artifact's `supersedes:` field naming an ID that still resolves to a live artifact, that names its own ID, or that is claimed by more than one artifact all fail; `checkLinks` names the successor when a dangling link matches a `supersedes:` entry elsewhere — ADR-034), bounded provenance (`checkProvenance`: inferred non-decisions declare low/high reversal cost and a high-cost member of an active capability's one-edge slice blocks activation, while inferred decisions remain a separately visible signature backlog), incident edges (`checkReality`: `reality: contradicted` belongs to analysis and links a capability or live criterion), README.md in every `/docs` folder, index-block integrity on taxonomy READMEs (`<!-- clue:index:start/end -->`: block links must exist, siblings and artifact-bearing subfolders must be referenced; separately, `corpus.IndexRowBacklog` counts rows whose label restates only their own link and `corpus.IndexDescriptionBacklog` counts rows that state their record but say nothing about it, and the CLI names both behind `--index-rows` — two disjoint reported populations, never an `Issue`, per [ADR-041](../../decisions/ADR-041-index-rows-state-their-record.md) and [ADR-046](../../decisions/ADR-046-index-rows-say-what-the-artifact-is-about.md)), constraint register fields (`source` non-empty, `enforcement: machine|partial|agent|human`, and the `**Checked by:**`/`**Residual:**` declarations `partial` and `human` owe — [ADR-017](../../decisions/ADR-017-conventions-are-constraints.md), [ADR-045](../../decisions/ADR-045-register-names-the-machine.md); the CLI reports the `agent` count as the promotion backlog and says nothing at zero), and the `--forbid-changes` gate.

2b. **Promoted conventions** (`corpus.checkTypeFields`, `checkProseLayout`, `checkSkippedTasks`, `checkProposalPlanItem`, `checkMilestoneStatus` in `conventions.go`, CH-110): the register rules that are about corpus *state*, each answering from the files in front of it. Per-type frontmatter extensions come from the `typeFields` map — `author`/`accepted-by` on decisions, `goal` on capabilities, with an empty `accepted-by` list counting as present and an unrecognized type checked against the core alone (C-009). Prose layout flags two running-text lines in a row, where a list marker opens text without being a continuation and fences, tables, frontmatter, blockquotes, HTML, and link definitions are structure (C-001). A `[-]` task under `changes/**/tasks.md` must carry prose after its checkbox (C-003); a `changes/*/proposal.md` must link a `P-`/`M-` identity or say `plan-less` (C-005); and a plan table declaring a `Status` column has its cells read against `todo | doing | done | dropped` (C-010). C-007 is human-held guidance: image links and assets are valid, and the choice between Mermaid, ASCII art, and SVG is reviewed for clarity rather than treated as a validation verdict.

**The edge these share:** they are properties of the corpus as it stands. `clue validate` never reads a diff, a base revision, or history — a verdict computed from a transition depends on the caller's branch and clone depth rather than on the bytes under review ([ADR-044](../../decisions/ADR-044-judge-reads-state-not-transitions.md)). The register's transition rules are held elsewhere: `.github/scripts/completed-plans.sh` freezes a completed plan (C-008), the release gates require a version section (C-002), and branch protection holds the merge boundary (C-012).

3. **Outward references** (`corpus.checkExternalReferences`, `corpus.checkForeignPointers`, CH-095): a reference pointing outside the repository names what it points at — a full address for anything that has one, the `clue:` identity form for an artifact in another repository's corpus — and a bare forge number fails with the line a reader opens to. The bare-number scan skips fenced blocks, code spans, link targets, labelled links, anchors, and local citations; the malformed-pointer scan skips fenced blocks and code spans, so a documented example of the form is never mistaken for a claim. The rule is pure text: resolving a target needs the network, so it lives in `clue refs` and can never reach a verdict ([ADR-040](../../decisions/ADR-040-qualified-external-references.md)).

4. **AC↔test contract and test-purpose taxonomy** (`corpus.checkACTests`, CH-003, CH-072, CH-073, CH-087, CH-089): canonical criterion tags use segmented uppercase prefixes, decimal digits, and optional lowercase suffixes under [ADR-037](../../decisions/ADR-037-brownfield-ac-id-grammar.md); test purposes follow [ADR-005](../../decisions/ADR-005-test-reference-convention.md)/[ADR-006](../../decisions/ADR-006-test-purpose-taxonomy.md). Framework-native tags are the general convention, and Go's `testing` has none, so the Go harvester reads normalized function-name prefixes (`TestAC<digits>_…`, `TestSNAPSQS<digits>_…`, `TestUnit_…`, `TestSanity_…`, `TestArch_…`) from `*_test.go`; Cucumber `.feature` tags are scenario-level. JVM evidence is conservative source attribution under [ADR-036](../../decisions/ADR-036-jvm-evidence-per-executable.md): one Java or Kotlin executable carries one canonical AC identity, proof type, and direction through literal JUnit method tags or the stable named-executable fallback, while class tags, unsupported syntax, and metadata split across methods receive no classified credit and a diagnostic. The checker fails an active AC without a test, an undeclared or retired AC reference, an unclassified Go test, or duplicate declaration. A scenario that declares `Test-type: Unit|Integration|E2E|Performance` additionally requires evidence classified with that type in both positive and negative directions; `(single-direction)` records the narrow exception. [ADR-032](../../decisions/ADR-032-classified-ac-evidence.md) defines the proof-shape contract and preserves the one-reference contract for unannotated legacy scenarios. `Test-type: Human` needs no code evidence at all — the acceptance brief is its proof — and a per-criterion `@draft` tag-line token exempts one not-yet-proven criterion from the test requirement without retiring it or drafting its capability ([ADR-033](../../decisions/ADR-033-human-proof-and-draft-criteria.md)).

5. **Derived coverage** (`corpus.Coverage`, `clue validate --coverage`): rolls each declared, non-retired criterion's evidence state up to its owning capability and prints `covered`, `partial`, or `gap` per capability, computed fresh from `harvestACs`'s shared declaration-and-evidence walk on every call — never written to disk, so it cannot drift the way a committed registry would (ADR-033).

6. **Derived reality gaps** (`corpus.RealityGaps`, `clue validate --reality-gaps`): rolls each incident analysis's capability or live-criterion links up to a sorted list of affected capabilities and the analyses that contradicted them. It reads only local corpus edges, writes nothing, and deliberately does not ingest production data ([ADR-035](../../decisions/ADR-035-bounded-provenance-and-reality-edges.md)).

7. **Identity ledger cross-check** (`corpus.checkLedger`, `internal/ledger`, CH-116): `clue id next <prefix>`, implemented separately in `cmd/clue`, allocates a numeric ID as an `internal/ledger` counter increment against `.clue/id-ledger.yaml` — an in-memory `byID` map and a per-prefix `counters` map populated by one `Load()`, never a corpus scan. After creating the artifact, `clue id live <id>` promotes only that reserved ID to `live`. `checkLedger` cross-checks the corpus once a ledger file exists (a corpus without one yet is unaffected): it rejects a live artifact whose ID is absent from the ledger or marked `reserved` or `retired`, and a malformed entry shape (a numeric-kind entry with no valid decimal component, or an opaque-kind entry carrying one). An opaque entry's exact canonical ID is never normalized or reissued once used, matching a numeric entry's counter never reissuing a retired component ([ADR-048](../../decisions/ADR-048-corpus-wide-id-ledger.md)). The ledger's own `reserved → live → retired` state machine and its backfill from an existing corpus (`internal/migrate` MIG-008, seeding one `live` entry per currently-live ID and each prefix's counter at its current max) belong to `clue migrate`, documented alongside CAP-001's other migration criteria.

## Deliberate limits (doors, not gaps)

- **Completed-plan immutability** — closed as a door rather than opened: it needs a base revision, which the judge will not have ([ADR-044](../../decisions/ADR-044-judge-reads-state-not-transitions.md)). It moved to CI, where a base is ordinary.
- **Layout linting beyond READMEs/indexes** — partly walked through by CH-110's prose-layout rule; a full markdown-shape profile remains a §4 default-on profile rule, later.

Exit codes: 0 valid · 1 issues · 2 usage error. Output is one `path: message` line per issue, sorted, so CI logs diff cleanly.
