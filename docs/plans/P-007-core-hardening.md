# P-007 — Cliewen hardens its core

P-006 digested the first adoption; this campaign digests the first critiques. Two independent reviews received 2026-07-25 — a methodology-level review and an enterprise migration assessment — reduce to four patterns recorded in [AN-008](../analysis/AN-008-methodology-critiques.md): the human half of the merge boundary is empty, the judge proves less than the skill prose promises, the graph only accumulates, and the whole loop is priced for the authoring repositories. Each pattern is a half-built face of a core element ([ARCH-003](../architecture/core.md)), so the campaign works core-first: the human gate, then judge honesty, then a corpus that can forget, then proportionate cost. It serves [G-001](../goals/G-001-verifiable-thread.md) — a thread whose human end is unstated and whose green is weaker than its claim is not verifiable in the sense the goal means.

Where a design already exists in the Intent Engineering book that Cliewen is born from — the after-gate human checklist, the coverage-pair convention with its single-direction exemption, the per-scenario test-type declaration, the spec-first review order — the milestone imports it rather than reinventing it, keeping Cliewen and the book coherent.

The campaign is sequential. Each milestone is a separate full Cliewen change rooted at accepted `main`, published as a ready pull request, and accepted by human merge before the next begins. Milestone numbering is corpus-global and continues from P-006 (M-024…M-029). M-024 through M-028 alter what a merge accepts or what a green validate asserts, so each is a red-line change under [C-013](../constraints/C-013-core-changes-need-decision.md): it carries its own explicit decision record and human acceptance, never riding silently.

## Explicitly out of this campaign

Adopter hardening that a real pilot must price first: CI-wall configurability (runner labels, pinned actions, binary location), a non-destructive extraction rehearsal pass, a blessed local-extension point beside managed skills, a configurable skills-mirror location, multi-prefix extraction handling, stacked or dependent changes, cross-repository evidence, and external-tracker metadata conventions. Also out: the production feedback loop beyond M-028's incident convention (the V3 door stays shut), any change to the book itself, changes inside adopting repositories, and reopening P-006's closed findings.
