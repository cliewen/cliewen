# P-010 — Cliewen makes staying current something an adopter notices

P-009 gave corpus releases a previewable mechanical upgrade path and closed on it. What it did not give anyone was a reason to run that path, or a place to learn it exists. `clue migrate` is stated once, in the operating guide on the public site, and an adopted repository carries no copy of that document. The word "upgrade" occurs in none of the five generated skills or their canonical sources, and the emitted routing hub names neither upgrading, migrating, nor versions — and that hub is the adopter's file, which `clue init` never overwrites and `clue migrate` never rewrites, so routing added there reaches new repositories only. Only skills reach an adopter who has already onboarded.

Worse than absent guidance is confident silence. An old binary carrying matching old skills validates green, and `clue migrate` on that pair reports "no changes needed" — a sentence an adopter reasonably reads as "you are current". Nothing in the system distinguishes being up to date from being unable to tell. The one moment a repository does learn something is wrong is the drift message, which names no command that would fix it.

Three backlogs were also routed forward across P-007, P-008, and P-009 without a campaign that owns them, and the judge now reports all three by count: 27 decisions still `inferred` and therefore agent-authored and never human-verified, 13 constraints whose only enforcement is an agent remembering to read them, and four capabilities that AN-007, AN-011, and AN-013 contradict. A methodology whose core promise is that humans verify meaning and machines enforce form cannot leave the majority of its own meaning unverified and the majority of its own form unenforced.

This campaign runs in two arcs. The first makes staying current visible and actionable: a command that reports a newer release and shows the recipe for the machine it is actually running on, routing that reaches existing adopters through a skill rather than through a file Cliewen may not touch, and discovery at the moment a coding agent starts or its context window is restarted. The second clears the three backlogs. Every milestone is a separate full Cliewen change rooted at accepted `main`, published as a ready pull request, and accepted by human merge before the next begins. Milestone numbering continues corpus-global numbering from P-009.

## Explicitly out of this campaign

**Simplification is deferred to P-011.** It is real work and it is deliberately not folded in here: a campaign that carries both would let "we should simplify first" postpone three backlogs that have already waited through three campaigns.

**The judge never reaches the network.** No milestone puts a network call inside `clue validate` or anywhere a validation verdict can read it. The separation is the point of M-045's decision record, not an implementation detail of it.

**`clue` does not replace its own binary.** The installation scripts verify every download against the release's published checksums and refuse to install on a mismatch; a self-updating binary would have to reimplement that verification inside itself, and a program that can overwrite itself from the network is a different kind of program than an offline judge. The convenience an adopter asked for is delivered by an agent following the skill, under the human merge boundary, not by the command.

**No milestone weakens the human merge boundary.** Nothing here lets an agent upgrade a repository and accept the result, and the automatic discovery in M-047 informs a session; it never acts on its own.
