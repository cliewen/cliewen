# P-008 — Cliewen agrees with itself before widening its promises

> **Completed 2026-07-30** — all milestones done; frozen immutable. Every live carrier now states one evidence contract, analysis says what its environment and its counts can prove, extraction rehearses before it mutates, and the two interface questions were answered with adopter evidence instead of design: no configuration interface and no distributed-work interface were built, because the measured needs were different ones. Successor designated: **P-009**, which consumes [AN-012](../analysis/AN-012-adopter-configuration-cost.md)'s and [AN-013](../analysis/AN-013-distributed-work-and-evidence-boundaries.md)'s routed candidates.

P-007 hardened the core and closed with every milestone evidenced, but [AN-011](../analysis/AN-011-methodology-self-consistency.md) found that several public and agent-facing carriers still describe the evidence model P-007 replaced. A mechanically green corpus whose live instructions disagree cannot satisfy [G-001](../goals/G-001-verifiable-thread.md): the thread is verifiable only when the judge, the skills, and the human-facing explanation state the same contract.

This campaign works from demonstrated contradiction outward. It repairs current truth before adding process, consumes the cross-trial analysis protocol before changing adoption, makes extraction reversible before asking a real adopter to price configuration, and uses findings rather than speculative interfaces for distributed boundaries. Every milestone is a separate full Cliewen change rooted at accepted `main`, published as a ready pull request, and accepted by human merge before the next begins. Milestone numbering continues corpus-global numbering from P-007 (M-032…M-036).

M-032 is deliberately the largest milestone and is not split. Its rule is that a contract change updates every carrier stating that contract in one change, and a repair that leaves the guide, the extraction skill, and the criteria in separate merges would be the first violation of the rule it establishes — an intermediate `main` would state the contract two ways. The reviewer therefore reads one wide but single-subject diff, all of it the same evidence-model claim restated per carrier, rather than several narrow diffs whose intermediate states are each incoherent.

## Explicitly out of this campaign

The production feedback loop beyond incident analyses, external constraint-catalog mechanics, and native validation of foreign documentation kinds remain future doors. A mechanical carrier inventory — declaring which carriers state which contract so a validator can flag the ones a change left behind — is a named door and not an M-032 deliverable: [AN-011](../analysis/AN-011-methodology-self-consistency.md) shows the obligation but supplies no evidence for what such a declaration would have to record, and a successor plan should open it only after M-032 and M-034 have exercised the prose rule on real contract changes. P-008 does not change the Intent Engineering book, adopt Cliewen into another repository without its maintainer's authority, or promise the interfaces M-035 and M-036 exist to investigate. Package-manager channels and already-closed P-006 findings remain closed scope.

## Mutation rules

Status and evidence fields in the milestone table may mutate in an implementing change's merge digest. Everything else changes only through a declared plan revision backed by a decision record routed by reversal cost. Plan adjustments are decisions.
