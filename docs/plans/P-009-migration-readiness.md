# P-009 — Cliewen closes migration blockers and distributed boundaries

P-008 ended with two adopter costs routed here: a copied CI wall whose first local edit severs upstream fixes, and corpus releases whose new obligations have no mechanical upgrade path. Its closing analysis also showed that ADR-009 delegates JVM per-test enforcement to an extraction-installed rule that extraction did not install. The implementation is weaker still for classified evidence: `checkACTests` combines every AC, proof-type, and direction tag found anywhere in one JVM file, so unrelated methods can produce a false green.

[AN-014](../analysis/AN-014-confidential-migration-assessment.md) records the evidence boundary of an anonymous migration assessment and reproduces its Cliewen-side mechanics without presenting the unavailable target repositories as verified evidence. Stable source criteria may carry multi-segment prefixes or letter-suffixed numeric identities that ADR-009's `<PREFIX>-<digits>` grammar rejects, making renumbering the only current route. The operating guide also leaves merge mode unstated even though a squash merge cannot retain a proposal created and deleted on its branch in `main` history. These are not convenience requests: false evidence, broken identity, and incomplete provenance contradict [G-001](../goals/G-001-verifiable-thread.md).

This campaign repairs migration truth before extending distributed-work contracts. It first removes false-green JVM attribution, then preserves stable source IDs, makes the supported merge-history contract explicit, removes the copied-wall fork, supplies mechanical corpus migrations, and ends the migration-readiness phase with a report-only rehearsal on a human-selected representative repository. Only after that evidence is in hand does it address the one distributed-work boundary an adopter meets in ordinary work: named but locally unproven foreign evidence. AN-013's other load-bearing boundary, durable dependent-change authorization, was scheduled here as M-043 and is now declined rather than pending — the review boundary already stops an agent before it builds on unaccepted work, and the decision log records what stays untrue without the interface. Every milestone is a separate full Cliewen change rooted at accepted `main`, published as a ready pull request, and accepted by human merge before the next begins. Milestone numbering continues corpus-global numbering from P-008; M-043 is a retired number that is never reused.

## Explicitly out of this campaign

Permanent dual-running remains outside Cliewen's adoption contract: the report-only rehearsal is the reversible checkpoint, while two accepted systems of record would make current meaning ambiguous. Structured proximity comments remain rejected; a JVM executable that cannot carry stable framework metadata or the named-test form is reported as unsupported rather than credited.

P-009 does not introduce a general `cliewen.yaml`, automate stacked merges, import a foreign green check as local proof, or make forge state the system of record. M-044 schedules AN-013's foreign-evidence candidate after migration readiness because it needs its own priced design and is not a prerequisite for one repository to migrate truthfully. AN-013's dependent-change candidate was scheduled as M-043 and is now declined outright rather than deferred: Cliewen records neither a dependent change's base nor its human authorization, and the decision log states what stays unreadable in history as a result. AN-013's qualified-external-reference candidate remains a named future door. Package-manager expansion and native validation of arbitrary documentation formats also remain outside this campaign.

## Mutation rules

Status and evidence fields in the milestone table may mutate in an implementing change's merge digest. Everything else changes only through a declared plan revision backed by a decision record routed by reversal cost. Plan adjustments are decisions.
