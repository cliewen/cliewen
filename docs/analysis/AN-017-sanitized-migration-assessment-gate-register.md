# AN-017 — The brownfield migration assessment re-derived as an inspectable gate register

## Evidence boundary

This is a sanitized record of the supplied brownfield migration assessment that originated P-011. It names no adopter. Its reported repository shapes, scale, and operational observations are supplied observations, not Cliewen evidence: this repository has neither the source revisions nor permission to reproduce them. The dispositions below are re-derived from the current corpus and commands, as PDR-026 requires.

## Re-derived gates

| Assessment gate | Present disposition | Basis |
|---|---|---|
| Historic identities must not be reused after source deletion. | Closed. | ADR-048's ledger, `clue validate`, and the M-056 numeric and opaque failure fixtures prove the mechanism and its failure paths. This repository now exercises MIG-008 to seed its own ledger. |
| Source criteria and their proof locations must survive extraction. | Closed at the declared fixture scope. | ADR-049's manifests and `clue parity` reject missing criteria, orphaned tags, changed directions or locations, stale fingerprints, and unjustified dispositions; AN-016 records the composed failure paths. |
| Active source work and operational carriers must survive deletion. | Closed at the declared fixture scope. | ADR-050 records durable imported work and ADR-051 reconciles carriers; AN-016 records their composed failure paths. |
| A migration must not hide corpus-wide debt behind repeated draft, Human, or retirement prose. | Closed at the declared fixture scope by M-058. | ADR-053 makes every deferred disposition name a readable source location and a distinct declared plan door, and `clue parity` reports the deferred population on every run; repeated prose no longer passes as a distinct deferral. |
| A durable extraction report must not contradict its own manifest. | Closed at the declared fixture scope by M-059. | ADR-054 renders a report's counts and mapping table from the pinned source manifest `clue parity` compares, and `clue validate` re-renders the region, so a typed or stale figure fails the required check. |
| A reviewer needs a committed per-criterion registry to read against a diff. | Declined with an accepted limit. | PDR-028 makes the refusal explicit: the derived report, pinned source manifest, and clean parity result replace the requested registry; an adopter gives up one diff-oriented document rendering every criterion and follows the manifest for individual mappings. |
| The contract must hold at the assessment's reported order of magnitude. | Closed at the declared fixture scope by M-061. | AC-128 holds the command surface at that size, including every deterministic parity and carrier failure class, and AC-129 holds the ordered path under a pinned release, including source-work preservation and the failure classes that path carries. The fixture is generated and disposable: this closes the gate for the contract, and still makes no claim about any production adopter's corpus, tests, or CI. |
| Adopter CI must have a reusable non-forking validation path and verified binary installation route. | Closed. | ADR-038's reusable workflow and ADR-030's verified install scripts supply the route; CAP-003's former claim that this remained unsolved is corrected in CH-122. |
| Hosted branch protection must not be mistaken for criterion proof. | Closed as an accepted methodology boundary. | PDR-027 distinguishes admission enforcement from acceptance evidence; a protected PR can enforce a gate, but cannot itself prove a criterion. |

## Result

P-011's five delivered mechanisms remain true at their stated scope. They did not close the four gates this register recorded as open or declined; P-012 is the successor campaign that takes them on, and M-057 makes this register and the repository's own ledger seed inspectable. Of those four, M-058, M-059, and M-061 are now closed at the declared fixture scope, and M-060 is declined with the accepted limit PDR-028 states. No gate this register records is still open.
