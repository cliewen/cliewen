# ADR-039 — Versioned corpus migrations plan safe mechanical upgrades

## Context and problem statement

Released `clue` versions may narrow a corpus contract while adopters still carry an older shape. A safe upgrade needs a preview, an atomic boundary around semantic choices, and a way to distinguish an unmodified generated carrier from a locally repaired one without hidden state or network access.

## Decision outcome

**`clue migrate` uses an ordered, versioned registry of idempotent mechanical migrations and plans the complete target before writing.** Preview is the default and `--apply` is explicit; preflight findings for missing semantic choices, unsupported syntax, missing carriers, copied workflows, or modified generated files prevent all writes, and applying rechecks the planned source bytes immediately before writing. Edits preserve line endings and all content outside the named field or managed carrier.

MIG-001 handles `reversal-cost` only when the adopter supplies an explicit value for inferred non-decisions; MIG-002 handles the historical architecture/analysis status values; MIG-003 handles generated skills, an optional Claude mirror, and the thin CI caller. Release manifests permit replacement only for recognized prior generated bytes, allow additions only under the complete recognized release set, and report missing or modified carriers. A missing Claude mirror is outside the write boundary.

Migration-registry changes require a `### Migration` section in that release's changelog entry. The judge remains offline and deterministic, and `clue init` remains non-destructive.

**Carrier:** `internal/migrate`, `cmd/clue migrate`, the embedded carrier renderer, release workflow guard, and migration guidance.
