# ADR-059 — Progressive standalone skill directories

## Context and problem statement

ADR-021 made every generated `skill.md` a complete standalone carrier so copying one file preserved every rule the skill could need. That boundary also makes invocation load every shared rule and every workflow branch before the agent knows whether the branch applies. Generation prevents authored copies from drifting, but it does not reduce the repeated reading cost P-015 addresses.

A skill already has a directory boundary. The directory can preserve standalone installation while its entry point routes to local reference material only when the work reaches the condition that material governs. The routing must be explicit: deferred rules that a reader is merely expected to discover are omitted rules in practice.

## Decision outcome

**A generated Cliewen skill is a complete standalone directory whose `skill.md` is a short routing entry point and whose deferred instructions live under that same directory's `references/`.**

- `skill.md` states the skill's purpose, the read-before-action boundary, and the condition under which each local reference must be read. A reference is mandatory when its named condition is reached, not optional further reading.
- Cross-cutting rules and detailed workflow branches may be deferred. No methodology rule is removed merely because it moves out of the entry point, and the generated directory contains every reference its router names.
- Copying one generated skill directory preserves its ownership marker, version stamp, workflow, and complete instruction set. A generated skill has no runtime dependency on another skill directory or on `internal/skills/source/`.
- Canonical sources remain centralized under `internal/skills/source/`. The generator emits every entry point and reference into both distributed trees, and drift checks cover missing, changed, and unexpected files anywhere inside each managed skill directory.
- Tests that assert a rule carried by a generated skill inspect the whole generated directory unless the contract specifically requires that rule in the entry point. Tests for routing separately prove that deferred material is named from `skill.md` and exists in the same directory.

This revises ADR-021's file-level completeness boundary to directory-level completeness. Its shared authoring source, deterministic generation, independent lifecycle entry points, byte-identical output trees, version stamps, and prohibition on dependencies outside the copied skill remain unchanged.

## Rejected alternatives

### Share one runtime reference directory between skills

One installed copy would reduce generated bytes, but copying or installing a single skill would silently omit rules and make the skill depend on repository layout outside its own directory. Canonical sharing remains an authoring concern; distribution stays standalone per skill.

### Treat references as optional background

Optional references lower apparent load by making required rules easy to skip. A route therefore names the condition that requires each reference, and reaching that branch obliges the read.

### Keep every cross-cutting boundary in every entry point

Repeating the complete review boundary, decision policy, and durable-work policy in each entry point preserves the current read cost. The entry point keeps only what must constrain action before routing; branch-specific detail moves behind the branch that consumes it.

## Carrier

`internal/skills`, both generated skill trees, ARCH-002, and CAP-004 carry the directory and routing contract.
